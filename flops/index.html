▸1 算力：一次前向、一步训练要多少 FLOPs

一次 forward 的 FLOPs

A(m×n) @ B(n×p) = 2·m·n·p FLOPs x[T,d_in] @ W[d_in,d_out] = 2 · token数 · 参数量

读这张表

矩阵乘每个输出元素是一次长度 n 的点积 = n 乘 + n 加，所以是 2mnp。 推论：数完参数量就等于数完 FLOPs——但只对带权重的行成立。

零 FLOPs 的行同样值得看：归一化、RoPE、softmax、残差加、拼头全是逐元素或换布局。 只有 Q@Kᵀ 和 scores@V 让 T 出现两次——T² 的唯一来源。

从一次前向推到一步训练

一步训练 ≈ 3 × 一次前向 AdamW 一步 ≈ 14·P

为什么是 3×

反向 ≈ 2 × 前向：每个权重矩阵反向要算两次——对输入的梯度和对权重的梯度。 AdamW 是逐元素的约 14 次运算，算力可以忽略，代价全在显存（第 2 段）。

▸2 显存：4P 是地板，saved tensors 是天花板

三笔账

常驻 4P　参数 + 梯度 + AdamW 的 m、v，各一份。和 batch、T 无关，全程占着。
saved tensors S　前向留下、反向要用的张量。随 B·T 涨，打分矩阵随 T²。
KV cache　只有推理有。

S 为什么留、又为什么能扔

对 Y = XW，∂L/∂W = Xᵀ·∂L/∂Y——算权重梯度得有当初的 X。 反向要等前向全部跑完，所以这些张量会同时堆着，这才是它成为天花板的原因。
但它能重算：梯度重计算多花约 30% 算力换掉大半，FlashAttention 干脆不物化 [B,h,T,T]。 4P 没这个余地。

名字取自 PyTorch 的 ctx.save_for_backward。 不叫「激活值」——和激活函数没关系，矩阵乘、softmax、归一化的输出全算； 也不叫 checkpoint——那个词在这里指的是相反的操作。

batch 怎么进来

tB = B × 累积 × 卡数。决定显存的是 B，累积和数据并行都不增加同时驻留的量。 但改 tB / 卡数 / 累积中任一个，B 都会变。

▸3 训练时间：token 预算 ↔ 天数，两头都能定
每 token 成本 = 3·F / T　　总算力 = 每 token 成本 × D 有效算力 = 峰值 × MFU × 卡数 天数 = 总算力 / 有效算力　　D = 天数 × 有效算力 × T / (3·F)

两头都能定

MFU 怎么来的

MFU = 实际用掉的算力 ÷ 峰值。填 token/s 反推 MFU，填 MFU 反推 token/s。 换算的桥是每 token 多少 FLOPs：业界常用 6·P，本页用精确的 3·F/T—— 6P 忽略了注意力的 T²、又把 0 FLOPs 的 embedding 算了进去。两个数都列在左边。

为什么 MFU 打不满：arithmetic intensity

AI = FLOPs / 搬运字节数 机器平衡点 = 峰值算力 / 显存带宽 AI > 平衡点 → compute-bound AI < 平衡点 → memory-bound
