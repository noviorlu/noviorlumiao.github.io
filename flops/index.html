矩阵乘每个输出元素是一次长度 n 的点积 = n 乘 + n 加，所以是 2mnp。 推论：数完参数量就等于数完了 FLOPs——但只对带权重的行成立。

零 FLOPs 的行同样值得看：归一化、RoPE、softmax、残差加、拼头， 全是逐元素或换布局，一次乘法都不做。

只有 Q@Kᵀ 和 scores@V 让 T 出现两次——那是 T² 的唯一来源， 下面「上下文拉长」整节都在算它。

一步训练 ≈ 3 × 一次前向 AdamW 一步 ≈ 14·P

为什么是 3×

反向 ≈ 2 × 前向：每个权重矩阵反向要算两次——对输入的梯度和对权重的梯度。

AdamW 是逐元素的：缩放、两次滑动平均、开方、除法、累加，约 14 次运算。 优化器的算力可以忽略，它的代价全在显存上——见第 2 段。

▸2 显存：4P 是地板，激活值是天花板

显存的三笔账

常驻 4P：参数、梯度、AdamW 的 m 和 v，各一份。和 batch、T 都无关，训练全程占着。

激活值 A：前向算出来、反向求梯度时还要用的中间结果。只在前向到反向之间存在， 和 B·T 成正比（打分矩阵还是 T 的平方）。

KV cache：只有推理有。训练一次算完整个序列，不需要缓存历史 K/V。

全局 batch 怎么进到这里

全局 batch tB = 单卡 micro-batch B × 梯度累积步数 × 卡数。 决定显存的是 B，不是 tB——一次前向只处理 B 条序列，累积和数据并行都不增加同时驻留的激活。 但 tB 通过这条链传导过来：改 tB、卡数、累积步数中的任何一个，B 都会变，这一段的数就跟着变。

真正吃掉的显存：4×参数 + 激活

一行 = 一个环节

一行三个口径：参数量（模型本身）、激活元素数（前向留下的中间结果）， 以及这行真正吃掉的显存。三列各自合到 100%。

最后一列才是能直接横向比的：显存 = bytes·(4×参数 + 激活)—— 参数按 4 份算（自己 + 梯度 + AdamW 的 m 和 v），激活按 1 份。 同样 1 个元素，权重比激活贵 4 倍。

权重不随 batch、不随 T 变；中间结果随 B·T 变。 一个形状 [in, out] 的权重作用在 B·T 个 token 上，产出 B·T·out 个元素—— 比值就是 B·T / d。

每 token 成本 = 3·F / T　　总算力 = 每 token 成本 × D 有效算力 = 峰值 × MFU × 卡数 天数 = 总算力 / 有效算力　　D = 天数 × 有效算力 × T / (3·F)

为什么 MFU 打不满：arithmetic intensity

AI = FLOPs / 搬运字节数 机器平衡点 = 峰值算力 / 显存带宽 AI > 平衡点 → compute-bound AI < 平衡点 → memory-bound
